# 2026-10-14

## 改造：精炼炉取消自动布局，改为「场景摆放位置 + 按名字顺序逐级出现」

需求：主场景 Wolrd 里手动摆了若干精炼炉（Furnace、Furnace2…）；
取消原先的精炼炉自动布局，位置按场景里摆的来；升级时按炉子名字顺序逐个出现。

### 改前的两处「自动布局」
1. `wolrd.gd::_place_furnace()`：每帧不参与，但开局把 `$Furnace` 强制挪到地图正中心
   （`MAP_SIZE/2` → 世界坐标 **(4128, 2336)**）。
2. `wolrd.gd::_spawn_furnace()`（「扩建精炼炉」升级时）：遍历全地图格子，
   选离所有已有炉子最远的一格，自动散布新炉子。

### 关键约束（改动时必须记住）
- 机器人和掉落物都靠 **`get_nodes_in_group("furnace")` + 距离**找炉子
  （`robot.gd::_find_nearest_furnace`、`dropped_item.gd`）。
  ⇒ 未解锁的炉子不能只是 `visible=false`，**必须退出分组**，否则机器人会跑去没出现的炉子卸货。
- `@onready var furnace = $Furnace` 被 `_setup_camera()`（相机初始目标）和 `_spawn_robot()`（机器人出生点）使用，
  所以 `_collect_placed_furnaces()` 必须排在它们**之前**。

### 改动清单
- `script/refining_furnace.gd`
  - 新增 `_is_active` / `is_active()` / `set_active(bool)`：
    停用时 `visible=false`、`input_pickable=false`、`set_process(false)`、**`remove_from_group("furnace")`**，
    并清空 `_smelt_timer`；启用时反向恢复。
  - `_process` 开头加 `if not _is_active: return` 兜底。
- `script/wolrd.gd`
  - 删除 `_place_furnace()`、`_spawn_furnace()`、`FURNACE_EDGE_MARGIN`、`FURNACE_SCENE` 预加载。
  - 新增 `_collect_placed_furnaces()`：从 "furnace" 分组收集 → `sort_custom(_furnace_order_cmp)`
    → 全部 `set_active(false)` → 只启用第 1 个，`_reveal_furnace_index = 1`。
  - 排序用「名字结尾数字」自然排序（`_name_tail_number`）：Furnace(0) < Furnace2 < Furnace3…
    数字相同再按名字比。
  - `_reveal_next_furnace()`：`add_furnace` 升级回调改为启用下一个（不再生成新节点）。
  - 自动同步科技上限：`GameManager.set_tech_max_level("add_furnace", maxi(1, 炉子数 - 1))`
    ⇒ 放 N 个炉子 = 开局 1 个 + 升级 N-1 级。（`maxi(1, …)` 保证 `unlock_more_ores` 的前置可满足）
- `GameManager.gd`
  - 新增 `_tech_max_level_overrides` + `set_tech_max_level()`；
    `get_tech_max_level()` 优先读覆盖值。
- `script/tech_tree_ui.gd`
  - `_make_tech_row` 里的 `tech.get("max_level", 1)` 改为 `GameManager.get_tech_max_level(tech_id)`，
    否则科技树 UI 看不到运行时覆盖。
- `scene/wolrd.tscn`
  - 给 `Furnace` 节点补上 `position = Vector2(4128, 2336)`（= 原来代码居中的位置），
    这样取消自动居中后视觉不变，用户可以再自己拖走。

## 追加：「扩建精炼炉」升级次数改成 5 次

需求：把精炼炉扩建的升级次数改成 5 次。

改动：
- `script/wolrd.gd`：新增常量 `FURNACE_UPGRADE_MAX := 5`；
  `_collect_placed_furnaces()` 里改为
  `GameManager.set_tech_max_level("add_furnace", maxi(FURNACE_UPGRADE_MAX, _placed_furnaces.size() - 1))`
  ⇒ 固定 5 次；若以后摆的炉子超过 6 个，上限自动跟着涨（避免多出来的炉子永远出不来）。
- `GameManager.gd`：`TECHS["add_furnace"]["max_level"]` 3 → 5，desc 改为
  「启用场景里预放置的下一个精炼炉，并行烧制（共 5 次）」，让声明的数据与实际一致。

用户此时已把 **Furnace5、Furnace6 保存进 `wolrd.tscn`**（并调整了部分炉子坐标），
当前场景共 6 个炉子：Furnace(4128,2336) / Furnace2(6880,3744) / Furnace3(3936,4000) /
Furnace4(1568,3936) / Furnace5(2208,1312) / Furnace6(6368,928)。

验证（副本 `F:/tmpgodot/check5`，headless 跑 test_reveal.tscn）：
Lv 0/5 开局只启用 Furnace；连升 5 级依次启用 Furnace2→Furnace6，
每次启用位置与场景坐标完全一致；5 级后 `can_unlock_tech` 为 false，Lv 5/5。

## 追加：「机器人数量上限」每级 +20 改为 +40

需求：机器人数量上限的升级，每次 +40。

改动（全部在 `GameManager.gd`）：
- `ROBOT_MAX_PER_LEVEL` 20 → **40**。上限公式 `get_robot_max() =
  ROBOT_MAX_BASE(20) + ROBOT_MAX_PER_LEVEL × get_tech_level("robot_count")`，
  `robot_count` 的 `max_level = 3` ⇒ 各级上限变为 **20 / 60 / 100 / 140**。
- `TECHS["robot_count"]["desc"]` 同步改成「（初始20，每级+40）」。
- 顺带修掉一个会失真的描述：`TECHS["reproduce"]["desc"]` 里写死的「上限80」
  改为「受「机器人数量上限」限制」（繁殖上限实际取 `get_robot_max()`，满级已变 140）。

调用的地方（无需改）：`wolrd.gd::_get_robot_max()`、`_spawn_robot()`、
`_tick_reproduce()`、`GameManager.can_unlock_tech("add_robot")`、
`research_lab_ui.gd::_get_tech_block_reason()` —— 全都走 `get_robot_max()`，无硬编码数量。

验证（副本 `F:/tmpgodot/check8`，headless 跑 test_robotmax.tscn）：
- Lv 0/1/2/3 → 20 / 60 / 100 / 140，逐级 +40 ✅
- 上限 60 时连续 `_spawn_robot()` 80 次：正好成功 60 个，第 61 次被拒 ✅
- 达上限后 `can_unlock_tech("add_robot")` = false（UI 文案「机器人已达上限 60」）✅
- 注：开局机器人 0 个是设计如此（`wolrd.gd::INITIAL_ROBOT_COUNT := 0`）。

## 追加：把机器人上限同步到「添加机器人」升级

需求：机器人上限要同步到「添加机器人」升级，达到当前上限就不能再添加机器人。

改前的问题：`TECHS["add_robot"]` 写死 `"max_level": 80`，与 `ROBOT_MAX_*` 脱节。
虽然 `can_unlock_tech("add_robot")` 里已有「机器人已达上限就拦截」的判断，
但卡片会显示「Lv 20/80」这种误导性的进度，两处数据各说各话。

改动（全部在 `GameManager.gd`）：
- `get_tech_max_level()` 增加特例：`if tech_id == "add_robot": return get_robot_max()`
  ⇒ add_robot 的等级上限**动态等于当前机器人数量上限**（20/60/100/140）。
  于是 `is_tech_unlocked("add_robot")`（= Lv >= 上限）在满员时自动为 true，
  UI 显示「已满级」且按钮禁用；买「机器人数量上限」后上限抬高，又能继续买。
- `TECHS["add_robot"]` 删掉写死的 `"max_level": 80`，并加注释说明上限来源；
  desc 补上「（上限跟随「机器人数量上限」）」。避免留第二个数据源。

验证（副本 `F:/tmpgodot/check9`，headless 跑 test_addrobot.tscn，真实走 `unlock_tech`）：
- robot_count Lv0（上限20）：add_robot 上限 20，正好买到 Lv 20/20 → 之后
  `is_tech_unlocked=true`、`can_unlock=false`、再买返回 false ✅
- 升 robot_count Lv1（上限60）：上限自动变 60，可再买 40 次到 Lv 60/60，场上 60 个 ✅
- robot_count 满级 Lv3（上限140）：上限变 140，再买 80 次到 Lv 140/140，场上 140 个 ✅
- 边界：繁殖把机器人顶到 140 但 add_robot 只有 Lv100 →
  `can_unlock=false`（拦住了）且 `is_tech_unlocked=false`（等级确实没满）✅
